# 数据导入回滚功能使用指南

## 功能概述

数据导入回滚功能允许用户撤销已完成的数据导入操作，将导入的数据从Elasticsearch中删除。

## 核心特性

1. **精确回滚**: 基于导入任务ID进行精确回滚，只删除该任务导入的数据
2. **安全预览**: 在执行回滚前可以预览将要删除的数据
3. **权限控制**: 用户只能回滚自己的导入任务，管理员可以回滚所有任务
4. **审计日志**: 记录所有回滚操作的详细信息
5. **批量操作**: 支持大批量数据的高效删除

## Web界面使用

### 1. 查看可回滚任务

在"数据导入管理"页面的"导入历史"标签页中：
- 查看任务列表，状态为"完成"且回滚状态为"未回滚"的任务可以进行回滚
- 点击"回滚"按钮开始回滚流程

### 2. 预览回滚

点击回滚按钮后会弹出回滚确认对话框，显示：
- 任务基本信息（任务ID、文件名、导入用户、导入时间）
- 回滚统计（总文档数、现存文档数、将被删除数、已缺失文档数）
- 数据样本（前5条数据的预览）

### 3. 执行回滚

在确认对话框中有三个选项：
- **取消**: 取消回滚操作
- **预演回滚**: 模拟回滚过程，不实际删除数据
- **确认回滚**: 执行实际的回滚操作

## 命令行使用

### 1. 列出可回滚的任务

```bash
python rollback_manager.py list-tasks
```

### 2. 预览回滚操作

```bash
python rollback_manager.py preview --task-id <任务ID>
```

### 3. 预演回滚（不实际删除）

```bash
python rollback_manager.py dry-run --task-id <任务ID>
```

### 4. 执行回滚

```bash
python rollback_manager.py rollback --task-id <任务ID>
```

### 5. 查看回滚历史

```bash
python rollback_manager.py history
```

## API接口

### 1. 预览回滚
GET /api/v1/rollback/preview/{task_id}
### 2. 检查是否可回滚
GET /api/v1/rollback/can-rollback/{task_id}
### 3. 执行回滚
POST /api/v1/rollback/execute
{
"task_id": "任务ID",
"dry_run": false
}
### 4. 获取回滚历史
GET /api/v1/rollback/history?page=1&page_size=20

## 注意事项

1. **不可逆操作**: 回滚操作会永久删除数据，无法恢复
2. **权限限制**: 普通用户只能回滚自己的导入任务
3. **状态检查**: 只有状态为"completed"的任务才能回滚
4. **重复回滚**: 已经回滚的任务不能再次回滚
5. **数据完整性**: 回滚只删除该任务导入的数据，不影响其他数据

## 故障排除

### 1. 无法回滚的常见原因

- 任务状态不是"completed"
- 任务已经被回滚过
- 任务没有记录导入的文档ID（老版本导入的任务）
- 权限不足

### 2. 部分回滚失败

如果回滚过程中部分文档删除失败：
- 检查Elasticsearch连接状态
- 查看错误日志了解具体失败原因
- 可以重新尝试回滚操作

### 3. 性能优化

对于大批量数据回滚：
- 系统会自动分批处理（每批100个文档）
- 避免在业务高峰期执行大批量回滚
- 监控Elasticsearch集群性能

## 技术实现

### 1. 文档ID追踪

- 每次导入时记录所有成功导入的文档ID
- 使用确定性算法生成文档ID，确保一致性
- 支持基于关单号、提单号或组合字段的ID生成

### 2. 批量删除

- 使用Elasticsearch的bulk API进行高效删除
- 分批处理避免内存溢出
- 错误处理和重试机制

### 3. 状态管理

- 任务状态：processing, completed, failed, rolled_back
- 回滚状态：none, pending, completed, failed
- 完整的状态转换和审计日志
